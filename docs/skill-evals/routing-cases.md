For the paired design cases, give both agents the same reservation adapters. One inserts on every call, the other returns the stored receipt for a repeated key. For the team review, use a candidate whose shared reader replaces zero with a default on both restore and refresh, whose old snapshots still use the previous field name, and whose refresh accepts a canceled result. Withhold the partner binary. For the shift change, start with a running archive job and a preview missing the last entry. Complete that same job between the pause and resume requests.

## Check the two review scopes

Give two fresh reviewers the same small repository excerpt and change only the request. In this example, the queue retries automatically when the network returns. A plan proposes a Retry button and accepts success if the item is eventually sent. Separately, the settings handler writes a draft before checking whether the user canceled. Its existing test covers only a confirmed save.

For a review of the retry plan, the finding should explain how automatic recovery can make a broken button pass the proposed check. For a repository improvement audit, the reviewer can also inspect the unrelated settings path and rank both opportunities using their effects and evidence. Neither result authorizes applying a fix.

## Check what survives a merge

Test the deliverable as well as the selected entry. Give a fresh agent the input and keep the expected behavior for the evaluator.

| Input | What the evaluator checks |
|---|---|
| Ask for requirements for offline inspections. Offline photos exist but disappear from the list. Submission by the inspector and retry are agreed. A supervisor wants automatic submission, continuous location was never approved, and draft ownership after logout is undecided. | The requirements distinguish an unreachable draft from missing capture. A Mermaid tree and its decisions agree about retained, provisional and pruned branches. The confirmed manual action survives. The logout decision blocks only the dependent branch. |
| Ask only why an export timed out. The UI timed out at 2,000 ms, the worker picked up the request at 2,400 ms, and the provider replied 50 ms after dispatch. A colleague suggests increasing the timeout. | The diagnosis locates the observed wait before dispatch and leaves the underlying worker delay open. It gives a check that distinguishes causes. A change to the timeout stays outside this request. An ordinary prompt rewrite still returns just the requested text. |
| Ask for a revised plan. A formatter and one verified caller already exist. A second caller is still unknown and project-wide formatting was never requested. | The plan retains valid evidence, gives a bounded discovery step for the missing consumer and ties each remaining deliverable to the accepted outcome. |
| Resume a two-entry change with `$dev-flow`, request a durable handoff, and stop at acceptance design. One current real entry has verified output. Only an older helper test exists for the other. | Carry the first artifact forward as verified. A repeat requires a relevant change or conflicting evidence. Give the next owner an actionable check for the second entry and leave implementation untouched. Try an existing record that names who chooses the on-call window, and a project with no record. Each finishes with one handoff. After a fresh agent resumes implementation, check that the original assignment and the pending field check survive. |
| Re-review an open finding on a repaired candidate. The passing test bypasses the affected consumer and the candidate has no output from that entry. | The report identifies the version, severity and evidence. It states which outcome passed and keeps the other finding open with its specific closure check. |
| An export must preserve row order, duplicates and missing labels. A proposed optimization batches label reads and sorts lookup keys. Ask one agent to reduce reads and another to review the claim that both changes help. | Compare the original and candidate on the same rows and count reads while checking the exported output. Remove batching and sorting separately from the candidate. Keep the simplest correct variant supported by the counts. The reviewer credits only the changes supported by evidence and ends at the report. |
| A counter Worker discovers that a shared stock interface reports both a missing record and a recorded zero as zero. One export consumer was already verified. Its owner approves the protocol change while the rest of the counter feature is unfinished. | The discovering Worker can update the contract, shared mock and examples in an isolated change. Integrate it early, notify affected owners of the new version and reopen the affected export check. Run the same examples against the real provider and verify both real outputs. Mock-only results stay identified. |
