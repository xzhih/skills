# Doc Driven Workflows

Maintain requested technical documentation or existing guidance made misleading by a change.

Ground facts in current code, configuration, tests, or observed behavior. Distinguish facts, design intent, and open questions; interpret external material for this project before promoting it into guidance.

Use the existing documentation structure. Give each fact one maintained home and link instead of copying. Create only useful architecture, operation, interface, or maintenance explanations; missing files alone do not justify a documentation system.

Update affected facts and links. Report changed documents, supporting evidence, and material gaps. Stay within documentation scope.
