# Explain an existing system

Read the installed `$explain` when available. It owns source walkthroughs, historical rationale and teaching. When working from this playbook alone, follow one real action to its visible result. For a complex UI, first locate the control and its state owner, then trace the same event through completion or cancellation. Show structure and timing separately when that makes the interaction easier to follow.

For historical intent, look for the introducing decision and later revisions in commits, PRs or design records. Attribute documented reasons and label inferences. Teach at the reader's pace, starting with the smallest example that answers the question. Answer in chat unless the reader asks for a saved explanation.
