# Dispatch and handoff

Dispatch within the authorized scope. Use the tool the user selected for this task. If none was named, follow the project's configured choice or use the current host's available delegation tool. Reuse confirmed model, host and review settings for the active roles. A discussion ends with the proposed assignments.

Use the selected tool's own skill or instructions to launch, monitor or resume assignments. Verify any required execution settings through that tool. If a required capability is unavailable, identify the affected assignment and continue independent work. Ask only when changing scope, cost, access or delivery needs the user's decision.

Send each Worker or Reviewer its brief and project inputs. Include a readable path for each designated `SKILL.md` and any supporting file required for the assignment. Each assignee reads them before doing the work, including when producing an independent candidate. If a path is unavailable on its host, supply the same revision at a readable location or send the full instructions for it to read. Until then, the assignee reports the missing file to its owner and holds that assignment. Other assignments can proceed.

On resume, check the current baseline, active assignments, landed contract changes and recorded evidence before dispatching again. Collect each Worker's candidate, observed results and remaining real-consumer checks. Update the existing handoff when continuity is needed.

For a shared real-entry check, give each assigned Worker the same project-relative procedure from the harness, guide or handoff. The Worker uses its own checkout and clean state, confirms readiness with the specified data, performs the real action, and reports the observed output and relevant side effects on its version. If the live instance is shared, isolate the data or run the checks in sequence.
